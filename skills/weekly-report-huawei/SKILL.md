# 华为责任结果导向周报生成器

## 何时用
用户给了一堆零散的本周工作（会议记录、bug 列表、commit、口头描述、甚至只是一段语音转写），需要生成一份可用于**邮件 / 汇报 / 述职素材**的周报。也适用于用户直接要"周报模板"。

## 核心原则（必须贯彻，缺一不可）
1. **价值闭环**：价值创造 → 价值评价 → 价值分配。周报的目的 = 帮领导明确"你的责任结果"，这是后续评价与分配的唯一依据。
2. **责任结果导向**（华为价值评价三导向之一：责任结果 / 贡献 / 商业价值）。不承认"茶壶里的饺子"——有苦劳无结果 = 零分。
3. **拧麻花张力**：从"事情本身应当如何去做"出发（客观、服务决策）+ 把责任结果显影在自己名下（用"我负责 / 我主导"）。**不自夸，让结果说话。**
4. **双维度呈现**：多打粮食（当期业绩：交付 / 修复 / 性能）+ 增加土地肥力（长期能力：流程 / 规范 / 人才沉淀）。
5. **复盘用其神，不入其形**：轻量复盘落在暗点节（问题→根因→改进）与亮点节（成功经验沉淀为规范）；完整 AAR 不在周报里堆。
6. **三条华为复盘纪律**：① 目的在**学习不在奖惩**；② 针对**事情和流程，不针对人**；③ **快速行动**，不反复分析。

## 输入要求
向用户索取（缺失也可基于已有信息推断，但必须标注 `[待确认]`）：
- 角色与责任领域（负责什么）
- 本周零散工作（任意形式皆可）
- 如有：量化数据、遇到风险、下周计划、需要的资源

## 转换映射（raw 笔记 → 结构）
| 用户原话 | 落到哪节 | 怎么改写 |
|----------|----------|----------|
| "做了 X / 修了 Y" | 二、亮点 | 拆成 责任 / 结果 / 贡献 / 数据，挂自己名下 |
| "遇到 Z 问题" | 三、暗点 | 问题 → 根因 → 影响责任结果 → 已动作 → 需支持 |
| "下周打算…" | 四、下一步 | P0 / P1 + 成功标准（可验收） |
| "缺人 / 缺资源" | 五、支持 | 当前缺口 + "资源到位后我能帮客户/同事/领导谁" |
| "某次成败" | 轻量复盘 | 意图 / 发生 / 学到 / 已做 / 已分享 |
| 任何亮点/暗点 | 一、关键结论 | 提炼 1 句话 + 3 个关键数字（含一项长期能力） |

## 输出结构（严格按此，邮件友好，无表格）
```
【一、本周关键结论】（领导先看这段）
- 我负责：…
- 结果：…
- 关键数字：① … ② … ③ …（含一项长期能力）
- 需领导决策：… / 无

【二、工作亮点（责任结果达成）】
1. 责任：我负责/主导 …
   结果：完成 …，状态 …
   贡献：对[客户/同事/领导] …；长期沉淀 …
   数据：…（量化对比）

【三、工作暗点 / 风险（主动暴露）】
- 问题：… → 根因：… → 影响的责任结果：… → 已动作：… → 需支持：…

【四、下一步行动（可验收）】
- P0：目标 … / 动作 … / 成功标准 …
- P1：目标 …

【五、需要的支持 & 资源到位后我能帮到谁】
- 当前缺口（要资源）：…
- 假如资源到位：帮客户 …、帮同事 …、帮领导 …

【六、用数据表态】（如涉及表扬/批评）
- …（纯数据，不情绪化）

【轻量复盘】（重大成败时写；平时可省略）
- …：意图 …；发生 …；学到 …；已做 …；已分享 …
```

## 质量要求（自检清单）
- [ ] 每条亮点都含**数据对比**（本周 vs 上周 / 目标）。
- [ ] 用了"我负责 / 我主导"，且区分了"参与"与"负责"。
- [ ] 语言简练，小标题纲举目张，开头就是给领导的决策信息。
- [ ] 涉及表扬 / 批评只用量化数据，无情绪化表达。
- [ ] 双维度齐备：既有"多打粮食"，也有"增加土地肥力"。
- [ ] 末节给出**可直接粘贴邮件的纯文本版**（同结构，去掉 markdown 符号，用 `-` 列表）。

## 邮件纯文本模板（直接填充 / 粘贴，无表格）

## 工作流程建议
1. 若用户只给了零散笔记，先按"转换映射"归类，对缺失项用 `[待确认]` 标注，必要时反问关键量化数据。
2. 生成**结构化周报**一份（markdown，便于存档/述职）。
3. 再生成**邮件纯文本版**一份（去掉 markdown，直接可发）。
4. 最后用"质量要求自检清单"过一遍，确认无流水账、无自夸、有数据。
