# 技术人员周报怎么写（华为责任结果导向 · 双模板融合版）

> 适用对象：即将/已入职华为的技术岗（开发 / 测试 / 运维 / 算法 / 研发负责人）
> 底层逻辑：**华为价值评价三导向 = 责任结果导向 + 贡献导向 + 商业价值导向**。周报的本质，是把"我负责的事"变成"可被评价的责任结果"，既服务领导决策，又自然体现自身价值。

---

## 〇、先想清楚一件事：周报为什么要用"责任结果"来写

华为判断一个人的回报，只看三件事的闭环：**价值创造 → 价值评价 → 价值分配**。
- 价值创造：以客户为中心，"眼睛对着客户，屁股对着老板"。
- 价值评价：**坚持责任结果导向**——不管加班多少、过程多辛苦，没有结果就没有评价（"不承认茶壶里的饺子"）。
- 价值分配：不让雷锋吃亏，利出一孔、多劳多得。

所以你的周报不是在"记流水账证明我忙"，而是在帮领导**明确"你的责任结果"**——这是后续评价与分配的唯一依据。

**这里有个"拧麻花"的张力，要处理好：**
- 周报目的是**帮助领导决策**，要**从"事情本身应当如何去做"出发**（客观、站在事情角度，而不是站在"我"的角度诉苦）。
- 但同时，你要**在其中体现自己的价值**——而华为式的解法不是自夸，而是**把"责任"和"结果"清晰地挂在自己名下**：我负责什么、结果如何、对谁（客户/同事/领导）产生了什么贡献。

> 一句话：**用"责任结果贡献"这条主线，把两套模板串起来，既服务决策，又显价值。**

---

## 一、两套模板各自的长处（先拆解）

### 模板一：决策导向 / 纲举目张
- 周报**开头是方便领导决策的关键信息**（领导 30 秒能抓住重点）
- 用**小标题，纲举目张**地展示信息/背景
- **语言简练**
- "**假如资源到位了我能帮到谁**（客户、同事、领导）"——这一步其实是在**展目标、要资源**

> 长处：站在领导/事情角度，结构清爽，天然服务决策。

### 模板二：亮点 / 暗点导向
- 工作**亮点**
- 工作**暗点**
- **下一步行动**
- **需要的支持**
- （如果需要表扬或批评）**用数据表态**

> 长处：正负两面都讲，诚实且有张力；"用数据表态"避免情绪化，符合华为"以事实分替代人情分"。

---

## 二、融合框架（推荐结构）

**用模板一的"外壳"（决策优先、纲举目张、简练）包住模板二的"内核"（亮点/暗点/行动/支持/数据表态），全部 grounded 在"责任结果贡献"上。**

```
【一、本周关键结论】（领导先看，决策用 —— 模板一外壳）
  · 一句话：本周我负责的【责任领域】，结果如何，对客户/项目/团队贡献是什么
  · 3 个关键数字（建议覆盖"多打粮食"当期业绩 + "增加土地肥力"长期能力）
  · 需要领导决策/拍板的事项（如有，直接点出）

【二、工作亮点（责任结果达成）】（模板二内核）
  按责任领域/项目，每条写清：
    责任：我负责/我主导的是什么
    结果：交付了什么、状态如何
    贡献：对客户/同事/领导的价值（+"增加土地肥力"的能力/流程/人才沉淀）
    数据：量化对比（本周值 vs 上周值 / 目标值）

【三、工作暗点 / 风险（主动暴露，责任结果视角）】
    问题 → 根因 → 影响的"责任结果" → 已采取的行动 → 需要的支持
  （不掩盖 = 对责任结果负责；这正是华为看重的"对关键事件负责"）

【四、下一步行动（可验收，对齐责任）】
    P0 / P1，每条：目标 / 关键动作 / 成功标准 / 对责任结果的承诺

【五、需要的支持 & 资源到位后我能帮到谁】（模板一"展目标、要资源"）
    当前缺口（要资源）
    假如资源到位：能帮客户___、帮同事___、帮领导___（= 展目标 / 责任可扩展范围）

【六、用数据表态】（如涉及表扬/批评 —— 模板二）
    表扬或批评，一律用数据，不情绪化、不模糊
```

## 三、如何"体现自己的价值"而不显自夸（华为式解法）

| 做法 | 说明 |
|------|------|
| **把责任挂自己名下** | 用"我负责 / 我主导 / 我推动"，明确责任边界；区分"参与"和"负责" |
| **双维度呈现** | "多打粮食"（当期业绩：交付、修复、性能）+ "增加土地肥力"（长期能力：流程、规范、人才培养、技术沉淀） |
| **用关键事件立住** | 华为用关键事件识别奋斗者：重大项目主要贡献、技术攻关、客户痛点解决。周报里点出你的"关键事件" |
| **量化 + 对标** | 数字 + 上下文（上周/目标），让贡献可评价、可分配 |
| **从"事情本身"出发** | 先讲"这件事应当如何做、卡在哪、怎么解"，再落"我的责任结果"——客观立场反而更显专业 |

> 核心：你的价值不是"写出来的"，是"责任结果"自己说话。周报只是把这条链路显影出来。

## 四、保留的硬技巧（之前版本的精华）

1. **黄金三角**：成果 + 价值 + 数据。
   - ❌ "优化了系统性能" → ✅ "P99 从 450ms 降到 220ms，预计减少用户流失约 3%"
2. **写问题用 STAR**：背景 → 目标 → 动作 → 量化结果。
3. **用业务语言**：工程师视角"重构 SQL 加索引" → 汇报视角"查询从 3s 降到 0.5s，可支撑 10 倍用户增长"。
4. **体现架构思维层次**：表面问题 → 直接原因 → 根本原因 → 解决方案 → 长远监控体系。

## 五、高分 vs 低分对照（华为风格）

**低分（流水账 + 自夸缺失）：**
> 这周修了几个 bug，写了点代码，参加了评审。

**高分（责任结果 + 双维度 + 数据）：**
> 【关键结论】本周负责订单域稳定性，P99 延迟 450→220ms（多打粮食），并沉淀《高并发幂等规范》一份（增加土地肥力）。
> 【亮点】主导修复订单高并发重复提交，补充幂等校验 + 3 条单测，已联调，预计下周二提测；对客户侧减少超卖客诉。
> 【暗点】测试环境 DB 频繁超时，已影响联调约 4h，根因疑似资源不足，申请运维协助诊断（责任结果：集成进度）。
> 【下一步】P0 优惠券核销上线；P1 推动《幂等规范》团队评审。
> 【资源到位后我能帮到谁】若加 1 名测试，可帮客户把验收周期从 5 天压到 3 天，帮领导提前 2 天释放交付风险。
> 【数据表态】本周线上缺陷 5→3（-40%），告警量 -35%，质量贡献可量化。

## 七、复盘 / AAR 在周报中的位置：用其神，不入其形

华为确实用美军 **AAR（After Action Review，行动后反思）** 做持续迭代，且把"自我批判"列为六大核心价值观之一。但 AAR 有六步（意图 → 发生什么 → 学到什么 → 可以做什么 → 行动 → 分享传播），是**项目 / 故障 / 里程碑后**的深度迭代；周报是**每周高频、轻量、服务决策**的工具。两者节奏不同，所以：

**结论：周报里要用复盘的"神"，不要搬 AAR 的"形"。**

- **轻量复盘（写进周报）落在两处：**
  1. **暗点 / 风险节**天然就是轻量 AAR：问题 → 根因 → 已动作 → 改进（对应"发生什么 / 学到什么 / 可以做什么"）。
  2. **亮点节**对重大成功补一句复盘：为什么成（关键动作），并把经验沉淀为规范 / 模板（= 增加土地肥力）。
- **完整 AAR / 复盘（不塞进周报，单独做）：** 项目结项、P0/P1 线上故障、关键里程碑达成后。产出必须"流程化"——复盘出的问题落到流程改进（如 IPD 年度优化），这才是华为式复盘的真价值。
- **华为式复盘的三条纪律（写周报也要守）：** ① 目的在**学习不在奖惩**；② 针对**事情和流程，不针对人**；③ **快速行动**，不反复分析。

**周报里的轻量复盘写法（把 AAR 六步压成 2-3 行）：**
> 【复盘·暗点】订单超卖事故：意图是零资损，实际因幂等缺失导致 3 笔重复（发生什么）；根因是并发校验未覆盖（学到什么）；本周已补幂等 + 3 单测并沉淀《幂等规范》（可以做什么 / 行动）；已同步给 2 个兄弟模块（分享传播）。

## 八、一句话心法

> **从"事情本身应当如何"出发帮领导决策，用"责任结果贡献"把价值显影在自己名下——既服务组织，也成就自己。**
